# M8.2 — Interactive stored security visualizations

Issue #70 (P1, GUI feature). Implementation candidate; target qualification pending. Extends the [M8.1 dashboard](SOC_DASHBOARD_M81.md), using the same authenticated, explicitly requested pages and expiry. No new dependency, network access, monitoring authority, persistence or raw evidence access.

## Data and semantics

| Chart | Scope and units |
| --- | --- |
| Event outcome histogram | Unknown, success, failure counts on the returned event page. |
| Receiver activity trend | Counts ordered oldest to newest in four receiver-age bins relative to the maximum receiver timestamp of the same page: >=3000, 2000–2999, 1000–1999, 0–999 ms. Oldest bin is open-ended. |
| Stored alert severity distribution | Counts by severity 0–5: unspecified, informational, low, medium, high, critical. All returned alerts by default; active filter includes open and acknowledged, not resolved. |

All charts use a fixed zero-to-eight-record bar scale and explicit numeric labels. No interpolation or rates; the trend bins are not a continuous time series, deployment totals or a sampling of live activity. Admission order is not timestamp order. The newest timestamp anchor is not changed by filters. Partial-page warnings remain in the corresponding M8.1 cards. A valid empty page has zero counts, while unavailable/expired/denied results have no bars or numbers. Unknown outcome and unspecified severity are data categories, not claims of missing coverage. Synthetic data is used only in isolated qualification, never generated by the desktop.

The native projection checks existing response bounds before counting; subtraction from the maximum avoids timestamp overflow, including full-width timestamps. Aggregates are fixed-size arrays and contain no identifiers or raw observations. Qt Quick renders at most thirteen rows; no chart animation, extra threads, polling, pagination or store queries. Activity outcome and alert lifecycle filters only select cached counts. Invalid filter codes are ignored. Clearing, refresh, expiry, disconnection and inconsistent manager instances remove aggregates and reset filters. Existing separate Events and Alerts models are unchanged. No new trust boundary or privileges.

## Qualification

The existing `knetsentry_dashboard_summary_contract` verifies counts, mixed outcomes/severities, active versus resolved, exact receiver-bin boundaries, extreme timestamps and empty/unavailable distinction. The existing `knetsentry_gui_dashboard_runtime` verifies actual QML chart bindings, 64 repeated local filter activations, denial, navigation clearing, exactly one authorized query per store and evidence invariance with the M7.7 fixture. Both tests retain their original registrations; run all seven presets and the structural verifier. Expected 562 configured CTests, 73 structural verifiers, 158 consolidated gates. Native boundedness does not establish GUI responsiveness at the planned operational workload.

Manual: create the private fixture as in M8.1; pass the exact printed IPC directory to the desktop and verify the socket exists. After refresh, histogram = 0/0/8; receiver bins = 0/0/0/8; severity = 0/0/0/8/0/0. Select Success: receiver bins all zero; select Failure or All: latest bin eight; histogram unchanged. Select Active only: medium eight. Refresh or leave Dashboard: filters reset. Wait 30 seconds, verify unavailable rather than zeros. Stop/restart manager, test disconnection, denial, compact/expanded layout and keyboard operation. Check other pages and clean shutdown. Use synthetic data only.
