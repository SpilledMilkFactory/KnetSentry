# M6.8 — Event Explorer GUI

Issue #58. Read-only inspection of an explicitly approved existing development
store. This is not operational ingestion, a production analyst-role service,
or evidence that monitoring is active. Target-host qualification is pending.

## Authority and activation

The foreground manager must receive `--event-store-dir ABS_DIR`, an explicit
`--ipc-dir ABS_DIR` and a separate fresh `--audit-dir ABS_DIR`. The manager is
non-root, retains the existing same effective UID/GID peer authorization and
private 0700 socket directory / 0600 socket checks, and requires a successful
persistent `events_authorized` audit write before disclosing a page. No endpoint
network permission, new capability, database path, SQL or mutation command is
accepted from the client. A default manager has no event query authority.

The manager opens only an existing schema-v4 `events-m64.sqlite3` through the
existing validated SQLite backend (`StorageOpenMode::ExistingV4`); no new store
or schema migration is initiated by inspection. All ordinary storage path,
locking, filesystem, schema and full bounded evidence-integrity checks remain
in effect. The existing SQLite implementation uses a read/write connection for
its transaction and recovery machinery; the manager exposes only a const search
interface, not a filesystem-enforced read-only database connection. The query
client never opens a database. Same-UID peers are one OS trust domain: this does
not isolate files from a compromised same-UID process or implement production
operator roles. A dedicated systemd manager is not configured for event access.

## Protocol and bounded search

`KSIPC/1 EVENTS` extends the existing four-byte big-endian length framing. Only
explicitly enabled managers accept event requests up to 256 bytes; other
operations retain the original 64-byte request bound. Responses are at most
4096 bytes. The existing nonblocking client checks socket ownership, mode,
connected SO_PEERCRED and complete frames, with a two-second exchange deadline.
The server uses its existing bounded serialized transport and audit machinery.

The fixed request grammar (spaces are literal separators, one terminal LF):

```text
KSIPC/1 EVENTS <16-lowercase-hex-id> <A|D> <mode|-> <outcome|-> <unit|-> <after> <revision> <session|->
```

The mode and outcome values use existing 0–2 vocabularies; `-` means omitted,
not Unknown. The source is exact, bounded, validated ASCII or `audit`. Initial
requests use `0 0 -`. Subsequent requests carry a positive last ID, positive
storage revision and the 32-hex manager instance identifier from the previous
page. The instance identifier is generated by `getrandom`, not an authorization
token. Same trusted client preserves predicates; session/revision mismatch
rejects continuation. The server supports dataset-wide ascending or descending
storage ID order, not chronological ordering. Both backends use identical typed
predicates; the SQLite backend binds values and revalidates candidates and all
retained commitments. Pending-index rows remain excluded. A nonmatching filter
cannot bypass integrity checking.

Response header:

```text
KSIPC/1 EVENTS <id> <OK|STALE|INTEGRITY|UNAVAILABLE> <session> <revision> <more>
```

Success carries at most eight rows, each with ID, source time (Unix ms),
receiver time (Unix ms), OCSF class, activity, outcome, mapping disposition,
collector mode and exact source unit. Severity remains Unknown, category follows
canonical class. Other outcomes have revision zero, `more=0`, no rows.
The client validates framing, correlation, all field ranges, canonical ASCII
source names, supported mapping/source combinations, predicates, page length,
ordering and continuation identity. It never receives raw messages, native
cursors, machine/boot IDs, bindings, credentials, digests or full canonical
records. No user-controlled strings are logged by the query service.

## Qt presentation

A C++ `QAbstractListModel` replaces rather than accumulates pages; Qt Quick
`ListView` uses delegate reuse. The UI provides explicit exact-source,
collector and outcome filters, backend ID ordering, first/next page and
selected normalized metadata inspection. Each page and detail is cleared on
refresh, filter edit, navigation away, failure or 30-second snapshot expiry.
An asynchronous timer advances the bounded nonblocking client; no SQL or
filesystem work runs in QML. Unknown severity is not a failed authentication
or a detection. Empty success is distinct from no configured source, malformed
responses, stale continuation or evidence integrity failure. There is no live
subscription. A snapshot may remain visible until expiry or refresh even if
the manager stops; it is explicitly labelled stored, not current live status.

The model retains at most eight rows; temporary response/decoded copies are
also bounded. Full integrity verification remains a backend scan of the bounded
128-record store, not a production throughput guarantee. The GUI currently
exposes a subset of the M6.6 query vocabulary; time range, binding, category,
severity and other advanced predicates remain storage-level features. No
raw-evidence detail or retention action is exposed. The manager query path is
an opt-in development bridge; operational receipt-to-store adaptation, role
authorization, query budget, authorization-bound continuation, independent
storage-volume approval and protected audit governance remain outstanding.

## Qualification

`knetsentry_event_explorer_contract` exercises the two real backends, known
ascending/descending filtered pages, pending exclusion, invalid input,
response parsing, peer-role checks and stale continuation. The
`knetsentry_event_explorer_runtime` fixture seeds a new disposable private
SQLite store, runs the actual foreground manager and native nonblocking client,
and tests opt-in, audit, missing database refusal, restart and integrity
failure. `knetsentry_gui_event_explorer_runtime` additionally launches the
actual offscreen GUI in nonsanitized desktop configurations (existing QML
sanitizer policy remains unchanged). The fixture includes 20 indexed records
and one pending record. The test executable's `--seed` option is for a newly
created empty 0700 disposable directory only, not a deployed evidence importer.
No real telemetry, credentials or privileged configuration is required.
